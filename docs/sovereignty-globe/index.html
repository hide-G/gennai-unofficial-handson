1. なぜ modelId ひとつでデジタル主権が変わるのか

Amazon Bedrock で InvokeModel / Converse を呼ぶとき、アプリが渡す文字列は 2 種類あります。 基盤モデル ID（プレフィックスなし）と、推論プロファイル ID（jp. / apac. / us. / eu. / global. 付き）です。 推論プロファイルは「モデル」＋「ルーティング先リージョンの集合」を定義したリソースなので、 プレフィックスがそのまま “データが処理される地理的範囲” を決めます。

ソースリージョン＝API を呼ぶリージョン（源内は東京）。デスティネーションリージョン＝Bedrock が推論を回す先。 ログ・ナレッジベース・設定などの保存データはソースリージョンに留まりますが、推論の演算そのものは宛先リージョンで起きます。 ここが「国内に閉じるか」の分岐点です。

2. 4 つの選択肢の比較

選択肢modelId の形宛先リージョン国内完結向いているケース

宛先リージョンの実データは本ワークスペースの AWS アカウント（東京リージョン）で bedrock list-inference-profiles を実行して取得した実測値です。

3. 源内での設定箇所

源内は modelId を設定として外部化しているため、主権の境界は「コード」ではなく「設定」で決まります。

// 源内Web（GenU 派生）: packages/cdk/cdk.json
"modelRegion": "ap-northeast-1",
"modelIds": [
  "jp.anthropic.claude-sonnet-4-6",                    // 東京・大阪に閉じる
  "amazon.nova-lite-v1:0",                             // 東京のみ（リージョン内）
  "jp.anthropic.claude-haiku-4-5-20251001-v1:0",       // 東京・大阪に閉じる
  "jp.anthropic.claude-sonnet-4-5-20250929-v1:0"       // 東京・大阪に閉じる
]

// 行政実務用 AI アプリ（query-expansion-rag）: config/apps/*.toml
modelId = "jp.anthropic.claude-sonnet-4-5-20250929-v1:0"
ここを global. や apac. に書き換えた瞬間、コード変更ゼロで推論が国外に出ます。 逆に言えば、レビュー対象は modelId の 1 行です。

4. 「国内に閉じる」を仕組みで担保する 4 点セット

① modelId を jp.（またはプレフィックスなし）に限定する

アプリの設定・許可リストで global. / apac. / us. / eu. を使わせない。

② IAM で宛先リージョンを明示的に列挙する

推論プロファイル ARN と、各宛先リージョンの基盤モデル ARN の両方が必要です。国内 2 リージョンだけを書くことで、意図が Resource に現れます。

{
  "Effect": "Allow",
  "Action": ["bedrock:InvokeModel", "bedrock:InvokeModelWithResponseStream"],
  "Resource": [
    "arn:aws:bedrock:ap-northeast-1:123456789012:inference-profile/jp.anthropic.claude-sonnet-4-6",
    "arn:aws:bedrock:ap-northeast-1::foundation-model/anthropic.claude-sonnet-4-6",
    "arn:aws:bedrock:ap-northeast-3::foundation-model/anthropic.claude-sonnet-4-6"
  ]
}

③ SCP でリージョンそのものを制限する

組織レベルで東京・大阪以外の Bedrock 呼び出しを拒否すれば、誤って global. を指定しても宛先が塞がれて失敗します（＝越境しない）。

④ CloudTrail の inferenceRegion で事後検証する

additionalEventData.inferenceRegion に実際の処理リージョンが記録されます。国内 2 リージョン以外が出ていないかを継続的に監査できます。

5. トレードオフ

  • 料金：日本国内 CRIS はグローバル分散に対して +10%（US / EU / オーストラリアの地理プロファイルも同様）。
  • モデルの選択肢：jp. があるモデルは限定的。最新の一部モデルは global. のみ。
  • スループット：宛先が 2 リージョンなので、全世界に分散するグローバル CRIS よりバースト耐性は下がる。クォータ増加はソースリージョン（東京 / 大阪）で申請。
  • opt-in リージョン：グローバル / 地理プロファイルの宛先には、アカウントで有効化していない opt-in リージョンが含まれ得る点に注意。
